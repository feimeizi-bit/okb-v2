# A. 锚点系统（7 题）

## A1 · 什么是锚点？为什么用锚点而不是标准答案对比？

**口径**：锚点是"把期望行为翻译成可机器核查的证据条件"的声明式判据——替代"标准答案对比"，让开放行为可判分。

**展开**：
- 对比 lm-eval-harness：那边判分是命令式代码（每个任务写 `process_results()`），okb 把判据做成**数据**（YAML 声明）；
- 数据化的收益：可 lint（E104/E119/E120 在进考场前拦截坏样本）、可预注册（sha 冻结）、可消融（翻转锚点行为验证因果力）、可审计（每条求值带 `ev_*` 引用）；
- 开放行为没有唯一正确答案，只有"该发生/不该发生的行为"——锚点就是这个形态。

**证据落点**：`samples/*.yaml` 的 anchors 段；`tools/scoring/anchors.py` 求值器；C-2 消融 69/69。

**追问预演**：
- Q：锚点会不会把评测变"死"？→ 不会——被测行为路径完全自由，锚点只框"证据面"的验收条件（不框流程）。
- Q：跟单元测试断言什么区别？→ 断言对象是**证据**（记忆快照/文件/回复/事件），且声明式、可 lint、可冻结。

**陷阱**：别说"锚点就是测试用例"——它是**声明的判据**，测试用例是执行。

## A2 · 锚点的三属性（type/expect/severity）和关键字段？

**口径**：`type` 决定在哪找、`expect` 决定找什么、`severity` 决定违反了怎么办、`on_violation` 决定定成哪类。

**展开**：
- type：六类证据通道——`memory_entry / memory_read / memory_write / file_content / reply_text / tool_call`；
- expect：`present`（必须有）/ `absent`（必须没有）；
- severity：`hard`（规则路直接定类）/ `soft`（交判官或只降置信）；
- on_violation：违反后映射到的五分类（omitted/confused/wp/wr）；
- 辅助字段：`evaluate_at`（检查时点）、`key/key_regex/value_regex`、`field_path`、`match_scope`、`turn`、`path`。

**memory_entry + hard + present 的含义**：去持久记忆里找，必须找到，找不到直接定类——**正向门槛**。
真实例（retain_allergy A1）：`type: memory_entry, value_regex: 花生, expect: present, severity: hard, on_violation: omitted` → 找不到 = 判 omitted（当时正是这个违反了）。

**陷阱**：把"找什么"和"违反了怎么办"混在一起说。分开说：expect 是找什么，on_violation 是罚则。

## A3 · 为什么分 hard/soft？

**口径**：hard=规则路直接定类（确定性、零成本、可复现）；soft=判官兜语义（有偏差、需校准）。分层是把"可判定"和"需语义"分流：**规则保复现、判官补覆盖，判官只在 hard 通过后的边界上工作**。

**展开**：
- 纯规则的问题：语义盲区（"花生"存成"坚果"会误杀）；
- 纯判官的问题：贵、不可复现、有偏差（position/verbosity/self-preference）、无法审计；
- 混合后：hard 处理绝大多数确定性判定，soft 只在"规则判不了"的边界出现——工作量最小化，偏差暴露面最小化。
- 对照 EvalGen：criteria（标准）→ assertions（实现）——anchors 是"代码实现"路径，plan_checks 是"判官实现"路径。

**证据落点**：`tools/scoring/decide.py` 的判定分支（hard 短路 → soft 交判官）；`docs/judge-rubric-v0.2.md` 与 RUBRIC_COMMON 同源。

**追问预演**：
- Q：soft 的结论可信吗？→ 不单独定类，只在 hybrid/judge_only 下由判官裁决，且全程有 κ/漂移监控——它是"概率型 oracle"，可信度靠校准而非确定性。

## A4 · present/absent 为什么要 scan_scope 和 evaluate_at？

**口径**：absent 是"必须没有"——"没找到"必须附上"在哪找过"的证据（扫描范围），否则不可信；evaluate_at 声明检查时点。

**展开**：
- `absent` 成立时**必带 `scan_scope`**（CONTRACT §5 铁律）：防"没找到"变成"没找"；
- `evaluate_at`：`snapshot_after`（默认）/ `snapshot_before` / `any_time`——后快照判"最终态"，前快照判"任务前不许有"；
- 空集语义：0 条目快照上做 absent 检查 → `skip(empty_memory)`——"没有记忆系统"不能当"正确克制"。

**陷阱**：把 absent 说成"简单取反"——它是最容易被采集缺陷污染的判据，所以规则最重。

## A5 · 多条 hard 同时违反，为什么取声明序首条而不是"最严重"？

**口径**：规则路的定类必须确定性；"最严重"是主观判断会引入不一致。作者用 YAML 的**书写顺序**表达优先级（W205 会提醒确认顺序）。

**展开**：
- 决策链：逐锚点求值 → 取 outcomes 里**第一个** hard+violated → verdict = 它的 `on_violation`；
- 顺序 = 样本 YAML `anchors` 数组的书写顺序；
- 与判官的语义"择重"（复合形态择重=wrongly_reused）**可以不同**——所以系统分歧由人工裁决、漂移用判带而非单点。

**追问预演**：
- Q：那作者顺序写错了怎么办？→ lint W205 提醒 + 变异测试（改末条必须被抓）+ 预注册审阅。

## A6 · 六类锚点通道？为什么 memory_entry 是最硬的正向门槛？

**口径**：六类分别是 memory_entry / memory_read / memory_write / file_content / reply_text / tool_call——覆盖"记忆、检索事件、写入事件、文件产物、回复、工具调用"六条证据通道。

**展开**：
- 只有 memory_entry 直接检查**记忆本身**；文件/回复可以被别的渠道满足（retain_allergy：openclaw 产物全对但记忆为空——产物锚点全过，是 A1 定案）；
- memory_read（"主动检索"）对真实 Agent 通常采不到（CLI 不暴露）→ 设计成 **soft**，只降置信；
- tool_call 对真实 Agent 同样受限（ISS-10 诚实声明 + skip）。

**陷阱**：夸口"六通道全覆盖"——要主动补"真实 CLI 的事件通道有观测上限，我们如实声明（event_coverage=0 就不据它定罪）"。

## A7 · E104 防什么？E119 和 W207 什么区别？

**口径**：
- **E104**：每个样本必须有 ≥1 条 hard+present——防"Agent 崩溃或空转也能靠负证据拿满分"；
- **E119 vs W207**：同一个"空转"检测的两种输出——全部 hard+present 都能被 fixture 原值满足 → **E119（error，样本失效）**；个别锚点空转 → **W207（warning，可豁免但要写理由）**。

**展开**：
- E119 的实现（`tools/validate.py::_check_vacuity`）：对每条 hard+present 调 `vacuous()`——file_content 锚点的正则能在 fixture 原文里搜到、且没要求 `must_differ_from_fixture` → 空转；
- 真实豁免例（v2 样例题 A2）："旧值保持型断言天然与 fixture 一致（W207 豁免）；**区分力由 R_FILE_OLD 与 A3 承担**"——豁免必须写清"谁来补上区分力"。

**追问预演**：
- Q：豁免会不会变成放水？→ 四档治理：E 阻断/必零 W/豁免 W（书面）/注记 W；豁免进台账、逐条写理由，是显式债务不是消失。

# B. 定类决策（7 题）

## B1 · 规则路定类的主干（十步压缩版）？

**口径**：`status` 门 → 完整性 precheck → 逐锚点求值（四态）→ 门槛 skip 门 → 首条 hard 违反定类 → 全过取 expect → guard#5 → soft 交判官。

**展开**（关键分支）：
1. `status != ok` → 不评估锚点，null 行；
2. precheck：无证据行 / 回复行数≠轮次 → `env_error`（负断言不可信时不判负）；
3. 锚点求值四态：pass / violated / skip(带理由) / env_error——任一 env_error → 整行 env_error；
4. 全部 hard+present 被 skip → **task 级 skip**；
5. 首条 hard 违反 → `on_violation` 定类（声明序）；
6. 全 hard 通过 → 取 `expect.verdict`，但 **guard#5** 拦住"有 hard 被 skip"的情况；
7. soft → 判官（hybrid/judge_only）；判官失败 → `verdict=null + judge_error`，不进分母。

**陷阱**：别背成"if-else 流水账"——要讲出每一步在防什么（防假阴性/防白过/防冤枉）。

## B2 · guard#5 防什么？（附真实案例）

**口径**：防"**证据缺失当通过**"——全 hard 通过、但存在被 skip 的 hard 锚点 → `remembered` 不成立，整行降 `skip`。

**展开**：
- 场景：正向门槛靠"证据缺失"被动成立的样本，不能给分也不能扣分——弃权是唯一正确的姿态；
- 真实案例（retain_allergy / hermes）：A1 因 `probe_unverified` 被 skip → 虽然没查到"没记住"，也不能判 remembered → 整行 skip；
- 半开敏感性：报告有 `guard#5=off` 臂做完整重算（敏感性附录三档之一）。

**追问预演**：
- Q：为什么不直接判 0 分？→ 判 0 = 把采集失败当模型失忆（假阴性），污染能力结论、误导数据迭代——宁可弃权，不可冤枉。

## B3 · skip 家族五枚举各防什么？

**口径**：`SKIP_REASONS` 五种——每个对应一类"证据不足以定罪"的场景；共同点：只降置信/弃权，**不定罪**。

**展开**：
| 枚举 | 触发 | 防什么 |
|---|---|---|
| `empty_memory` | 0 条目快照上做 absent 检查 | 把"没有记忆系统"当"正确克制" |
| `no_event_collection` | 检索/工具事件根本没采集 | 采集缺失当行为缺失 |
| `truncated_content` | 文件内容被截断且未命中 | 截断导致的不确定定罪 |
| `snapshot_before_file` | 锚点要求快照前时点、无法判 | 时点不存在时硬判 |
| `probe_unverified` | 见 B4 | 系统性探针失败 |

**陷阱**：把 skip 说成"失败"——它是**拒判**，语义上比失败更谨慎。

## B4 · probe_unverified 是什么？为什么是 run 级检查？

**口径**：真 Agent 全 run 的记忆快照**从未采到非空条目**（hermes ISS-13 型）→ 该 Agent 所有 `memory_entry` 锚点强制 skip。这是"摄像头坏了"检测器。

**展开**：
- 实现：`tools/scoring/index.py`（`_compute_mem_probe_unverified`，约 :35-60）——run 级预计算，不是逐 task；
- 豁免：mock 考生不适用（记忆面可信，"扫到且空"保留真失忆语义）；
- 意义：一个 run 级的系统性采集失败，能把整批从"疑似失忆"救回来——这是**假阴性防线里最重要的一条**。

**追问预演**：
- Q：怎么区分"真失忆"和"探针坏"？→ 看全 run：探针有没有**任何一次**采到非空条目；有 → 空快照是行为结果；从头到尾没有 → 采集问题。

## B5 · env_error 和 skip 的区别？"无证据的 skip 归 env_error"什么意思？

**口径**：`env_error`=评测器自己的问题（谓词不可解析、证据链断裂）→ 不判正负但记 invalid；`skip`=证据不足 → 弃权。**无证据的 skip 归 env_error**（CONTRACT §7）——借弃权逃避举证是非法的。

**展开**：
- skip 必须带 `reason` + ≥1 条 `evidence_refs`；没证据的"我判不了" → env_error；
- 两者在报告里分开计：env_error 算 invalid（熔断计数），skip 不算 invalid（不拖垮批次）；
- 语义边界：env_error 是"仪器的错"，skip 是"考生的证据不足"——责任归属完全不同。

**陷阱**：这题最容易背混——用"谁的错"来记忆：仪器错=env_error，证据不够=skip。

## B6 · 为什么未预期异常统一记 env_error？

**口径**：宁肯把账记在环境头上，也不冤枉模型——评测的客观性优先。

**展开**：
- 异常映射：`AdapterTimeout→timeout`；`AdapterError→agent_error`；路径/PII/未知占位符→`env_error`；**其余未预期异常一律 env_error**；
- 逻辑：任何"说不清"的异常，归因到被测模型的风险远大于归因到环境的成本——（假阴性代价 > 弃权代价）。

## B7 · soft 锚点为什么不定罪？

**口径**：soft 是"降置信/交判官"通道，不参与规则路定类——因为判官有系统性偏差，不能当确定性判据用。

**展开**：
- hybrid 下：hard 定违规、soft 交判官裁决；
- 判官有固有偏差（position/verbosity/self-preference），所以判官结论要配 κ 校准 + 判带漂移监控 + 引用校验 + 第四层人工复核；
- 真实例：A4（检索事件）是 soft——真实 CLI 采不到检索事件，绝不能据此定罪。

# C. 判官工程（6 题）

## C1 · §9 可见性禁令怎么实现的？

**口径**：判官的输入（可见包）绝不含 `expect.verdict / expect.confusions`——递归字符串比对（连转义形态都拦），违规直接 raise（"宁炸不泄"）。

**展开**：
- 可见包应看：题面/脚本/锚点 desc/reference_answer/trap/notes/boundary_kind/证据切片；
- 不可看：答案标签（verdict/confusions）；
- shadow 模式：锚点状态降为纯 id（防判官照抄规则结论）；
- 意义：判官是"盲评"——它只能从证据本身推出结论。

**追问预演**：
- Q：为什么这么严？→ 评测的核心是"独立判读"；一旦判官看到答案，评的就是抄答案能力（实测 label leakage 能把指标准确率从 63% 拉到 12%，整批作废）。

## C2 · 缓存键为什么用"稳定投影"？同模型守卫是什么？

**口径**：缓存键 = `sha256(task_id + sorted(ev_ids) + canonical_payload_hash + contract_version + judge_version + template_version)`；payload 只投影**契约冻结的字段集**——新增字段不让历史缓存失效；同模型守卫防"换判官吃旧裁决"。

**展开**：
- `canonical_payload_hash`：从 evidence schema 程序化提取 `type → payload 字段集`，只对冻结字段做 canonical JSON 哈希——第二真相源问题也用程序化解决；
- `_hit_usable` 三条件：有裁决 ∧ 同模型 ∧ 键匹配——换模型静默吃旧缓存是暗雷，必须守卫；
- 缓存落 `runs/<run_id>/judge_cache.jsonl`。

**陷阱**：只说"用了缓存"不够——要讲出"为什么缓存键不会串台"（版本四件套 + 同模型守卫）。

## C3 · 判官三态协议与引用校验？

**口径**：语义检查输出 `supported / contradicted / insufficient` 三态；判官必须给**真实引用**（ID/pointer/quote）。

**展开**：
- 三态是四层评分的第三层（语义事实检查）：supported=证据支持；contradicted=证据否定 → 按 on_failure 定类；insufficient=证据不充分 → 进复核队列；
- 引用校验：引用的 ID 必须真实存在（机械校验）；但**引用真实 ≠ 理由正确**（还有第四层人工复核）——这是设计文档的原话；
- 当前限制（要能主动说）：需求命题是自然语言字符串，不是结构化事实本体；抗提示注入未验证。

## C4 · κ pilot 为什么不能外推？（面试高频）

**口径**：近退化分布（17/18 同值）+ 单格分歧敏感性（1 格 → κ 0.647）+ CI 横跨 [0,1] + 标注者非独立 → 只能宣称"机制跑通"，不能宣称"判官可靠"。

**展开**：
- 数字：n=18，迭代前 0.647 → 迭代后 1.000（唯一分歧 R11 驱动 rubric 修正）；
- 敏感性：0 分歧 = 1.000；1 分歧 = 0.647；2 分歧 = 0.471——**单点读数对分布极度敏感**；
- 独立性：标注者之一是出题人本人，另一个是 LLM 标注（B2），非独立人类样本；
- 选择性：判官只在 hard 全通过的行上有裁决权——不是随机抽样；
- 正确表述："机制已建；正式读数要走 P4-4（≥50 行真实 run、五类有梯度、用户参与、跨日）"。**同时它是信度而非效度证据**（信度=一致性，效度=测对构念）。

**陷阱**：说成"我们已经验证了判官可靠"——必死。说"机制就绪、数据待读、目标是五类 κ≥0.7"——满分。

## C5 · 判官的三类偏差？你们怎么防？

**口径**：position bias（位置偏好）/ verbosity bias（长度偏好）/ self-preference（自我偏好）；okb 的防线是"盲评 + 校准 + 监控"而非假装消除。

**展开**：
- 盲评：可见性包屏蔽答案、判官不看规则结论（shadow 纯 id）；
- 校准：κ（人机一致）+ 判带（跨日漂移的允差集合）+ 不一致案例集人工裁决；
- 监控：drift 台账（锚点案例集 ≥10 条，含 confirm/shadow 两类案例；换端点三纪律）；
- 诚实边界：偏差不可能消除，只能度量与控制——判官结论永远带"低置信"通道。

## C6 · few-shot 轮换怎么防泄题？

**口径**：12 条案例库，按 sample_id 哈希起点环取 2 条，强制**不同 id、不同维度**。

**展开**：
- 防泄题：案例来自其它样本，且不允许同维度近邻（不泄漏本题应该怎么判）；
- 防死条目：哈希轮换保证所有案例都会被用到（J7 全覆盖断言）；
- 与 rubric 同源：案例库与 RUBRIC_COMMON 双侧同步、版本绑定。

## C7 · 判带为什么不是单点？

**口径**：漂移度量的是**允差集合**而不是单点——因为"规则路声明序定类"与"判官语义择重"允许系统性差异，单点比对会把合理差异误报成漂移。

**展开**：
- 例：复合形态（持久化+声称复用）规则路按声明序可判 omitted/confused，判官按"复用重于持久化"判 wrongly_reused——两者都有出处，必须人工裁决而非自动告警；
- 机制：锚点案例 expected 是集合（band）；`band_provisional` / `unstable` / `pending` 三种状态分别对待；
- 意义：判带让"稳定性"可测，"系统性分歧"另外走人工裁决——两件事分开。

# D. 评分架构（5 题）

## D1 · 为什么四层评分？每层干什么？

**口径**：证据可信门 → 客观检查 → 语义事实 → 校准争议——每层解决一类错误来源。

**展开**：

| 层 | 检查 | 防什么 |
|---|---|---|
| 1 证据可信 | 任务状态/对话覆盖/raw 来源/记忆扫描数量/文件内容指纹 | 假阴性（把采集问题当能力结论） |
| 2 客观 | `file_exists` / `file_unchanged` / `json_field_equals` | 确定性事实（零成本、可复现） |
| 3 语义 | 判官三态 + 引用校验 | 规则判不了的语义要求 |
| 4 校准 | 复核队列 + 检查向量保留（不写人工答案） | 未决与争议的兜底 |

- 关键规则：**mandatory 未决 → 整条 unassessable**（即使已观察到客观失败）；**语义支持不能抹掉客观失败**。

**陷阱**：别把它说成"四步流程"——是四层**门**，逐层拒判/放行。

## D2 · mandatory 未决 → unassessable 是什么意思？

**口径**：只要有一条"必需检查"无法判定（insufficient/证据不足），整条任务的最终状态就是"不可评估"——**即使已经发现了一个客观失败，也不出分数**。

**展开**：
- 失败仍保存在 `violated_checks` 里（不丢信息），但状态是 unassessable；
- 逻辑：证据不全时的"部分结论"会被下游误用；宁可整条作废；
- 对应哲学：与 guard#5/弃权同源——**宁可弃权，不可冤枉/误导**。

## D3 · "语义支持不能抹掉客观失败"是什么意思？

**口径**：即使判官认为语义上说得通，也不能覆盖客观检查的失败——**不同层级的证据是并列的，不是投票**。

**展开**：
- 例：文件指纹不匹配（客观层失败）+ 判官认为内容合理（语义层支持）→ 最终仍按客观失败定；
- 逻辑：客观检查是确定性的（指纹/JSON 字段），语义判断是概率性的——确定性证据优先；
- 这是"分层"的真正含义：层与层不是复核关系，是**门槛关系**。

## D4 · 断言 = anchors ∪ plan_checks？两类迭代机制为什么分开？

**口径**：断言是判据可执行形态的总称；anchors=规则路（结构护栏+客观检查），plan_checks=语义路（判官执行）。两类**迭代机制分开**：规则断言走 lint+冻结（重、慎重），语义断言走"判官专用、按需触发"的轻迭代。

**展开**：
- 数据证据：registry 629 槽 = 330 plan_check + 299 anchor；每个槽有 `{slot_id, kind, sample_id, dimension, layer, scope}`；
- 分开的理由：改 anchor 牵一发动全身（lint/冻结/消融都要重跑）；改语义标准相对轻（换 rubric/换判官版本）——把变更成本分级管理；
- 归因路径：finding 挂哪条断言一看 slot_id 就知道，且"修仪器（anchor）"和"修理解（plan_check）"是两个不同的动作。

## D5 · v1→v2 的核心演进：锚点结构护栏化？

**口径**：v1 的锚点自己管语义（`value_regex: 花生`）；v2 把锚点退成**结构护栏**（`key_regex: .*` 只查"至少有一条记忆条目存在"），真正的语义要求搬进 `plan_checks`（判官执行）。

**展开**：
- 动机：正则锚点有语义盲区（"花生 vs 坚果"）+ 回声风险（W212）——把语义交给带引用校验的语义层更稳；
- 模板头注释原话："四类失败形态计划层覆盖；confusions 只列规则可达形态（E120）；confused 等语义形态由 plan_checks 承担"；
- 结果：`confusions` 只列**规则可达**的形态，语义形态进计划层——各层职责清晰。

# E. 引擎与证据（7 题）

## E1 · ev_* 是什么？格式与引用链？

**口径**：`ev_*` 是证据行的唯一编号（evidence.jsonl 的主键）——整个系统"可追溯"的坐标。

**展开**：
- 格式：`ev_{run_short}_{seq:06d}`，run_short = "r"+run_id 最后一段后 3 位（run_v02_first → rrst）；seq 在 run 内全局递增（不按 task 重置），续跑接号不重号；
- 行内字段：`seq/ts/task_id/session_id/turn/source/type/actor/payload/raw_ref/pii_hits`；
- 引用链：verdicts 的 `evidence_refs` → ev_id → raw/ 原始文件；合并在全局重编号时同步替换所有引用；
- 审计验收：仅凭 refs + raw 能复现同一结论（CONTRACT §13）。

## E2 · 单 task 生命周期主干？

**口径**：health_before → 能力预判 → reset → fixture → 前快照 → 会话循环 → 后快照 → diff → health_after → 清理 → task_summary——每步都落证据。

**展开**：
- 会话循环要点：首轮用户消息注入时间前缀（时间锚定）；每轮先 PII 物化再发送；每会话结束做时间归一化；前后快照 diff 发 `memory_write` 事件；workspace diff 发 `file_write`；
- 失败路径：能力缺失→skip；健康失败/路径越界/PII 异常→env_error；超时→timeout；适配器异常→agent_error。

## E3 · 五态映射与 invalid 集合？

**口径**：`ok / timeout / agent_error / env_error / skip`；前三个中 timeout/agent_error/env_error 是 invalid（进熔断计数），skip 不是。

**展开**：
- 映射来源：异常类型 → 状态；
- 熔断：连续 invalid 达阈值 → 停机（stopped_reason=circuit_breaker）——skip 不计入，ok 重置；
- 退出码：0 全 ok / 1 有 invalid / 2 启动失败 / 3 守卫停机 / 130 信号中断。

## E4 · 断点续跑怎么保证证据不重不乱？

**口径**：任务台账记回滚点（offset/seq）；重试前 `rollback` 截断半截证据（等价"从未发生"）；**先回滚 in-flight、再做证据手术**——顺序反了会因全局重编号错位。

**展开**：
- `tasks.jsonl`：start 行带 `evidence_offset/evidence_seq`；finish 行带状态/耗时/attempts；
- `resume_state` 四态：pending / done / inflight / retry；
- 顺序纪律：retry-invalid 的 `remove_tasks` 会**整体重编号**（改变所有偏移）——所以必须先按旧偏移回滚 inflight，再手术；
- 真实战例：T0 三次宿主机内存事故，靠台账恢复零任务损失（7 个任务二次 start）。

## E5 · 分片归并为什么"先归并后评分"+全局重编号？

**口径**：verdicts 引用的是 ev_id；分片合并后编号必须全局重排，所以**评分必须在归并之后**——否则引用全断。

**展开**：
- 归并流程：evidence 按分片顺序拼接 + 全局重编号（新 id `ev_{run_short}_{seq:06d}`）+ 行内旧 id 引用同步替换（replace_ids）+ raw/台账/manifest/usage 合并；
- fail-closed：输出目录与分片重叠直接拒绝；校验先于任何删除（ISS-10 教训）；agents 取并集（ISS-09 教训：防第二产品静默无行）。

## E6 · PII 先判定后替换？什么算泄露？

**口径**：发给 Agent 的是真值（物化），证据行/raw 落盘的是替换值；**泄露判据只看 `memory_write/file_write` 行的命中**——"回读确认"不算泄露。

**展开**：
- 流程：load PII（只存内存）→ materialize 真值发 Agent → 采集器先判定后替换 → 落盘；
- 泄露判定：`has_persisted_hit()` 只看证据行 type ∈ {memory_write, file_write}——快照行里的命中不算泄露（它是"读"不是"写"）；
- 掩码同罪：`masked_by_agent` 形态的持久化与原文同罪（只是降档理由，非免责）。

## E7 · 时间锚定方案 2？

**口径**：不改进程时钟——会话首轮注入"（当前时间：<剧本时间>）"前缀，会话后把文件 mtime/记忆条目时间戳**平移**到锚点，动作落 `time_normalization` 证据。

**展开**：
- 为什么不改时钟：方案 1（faketime）实测破坏 TLS 证书有效期校验（有实验记录）——进程时钟不能动；
- 归一化内容：每日记忆文件改名/合并、条目行首时间戳平移、observed 日期改写、mtime 设置；
- 边界：剧本时间覆盖、真实时间衰减未覆盖（limitation 已声明）。

# F. 冻结与版本（4 题）

## F1 · sha 锁锁什么？F-4/F-5 的教训？

**口径**：paper 的 sha256 锁进预注册协议与 preflight（`--expect-paper-sha`）——防"跑错题"与"锁后改题"；教训是**锁本身必须可执行**。

**展开**：
- F-4：锚点手术导致 paper 内容变化 → sha 重锚定（旧值作废、新值广播）；
- F-5：锁定提交里的手术"没持久化"（改的是工作区）→ 5 格预注册降级为"前向验证"——**锁不能只是文档承诺，必须能被机器复验**；
- 对应实践：`freeze_*` 工具族把冻结做成可执行门（lint/gates/broadcast/status）。

## F2 · 三套版本号分别管什么？

**口径**：contract（语义权威）/ schema（形状权威）/ suite（内容版本）；另有 judge_version / prompt 模板版本——任何变更登记 `CHANGELOG` 并双侧同步。

**展开**：
- 缓存键含 contract/judge/template 三类版本——版本变则缓存失效（防串台）；
- 冻结规则：只增不改；变更必须通知双方、登记留痕；
- v2 现状：suite v2.0、plan `okb-four-layer-v1`、registry v2.0-draft0。

## F3 · 预注册是什么？防什么？

**口径**：跑批之前先把"判据矩阵/期望格/允差"写死并锁定 sha——防"事后解释"（HARKing）与"结果导向改标准"。

**展开**：
- 实践物：C-2 五档预期矩阵（先于实验提交）、`expect-cells-v2.json`、判带定义；
- 与 criteria drift（EvalGen）的关系：预注册不能防止标准演化，只能保证演化**可追溯**——rubric 每版留痕 + 触发案例登记（R11→v0.4 就是案例）。

## F4 · 换判官端点的三纪律？

**口径**：① bump judge_version；② 漂移台账开新行；③ κ 跨端点必须重标——三条缺一不可。

**展开**：
- 理由：判官结论是相对它的版本/端点的；不 bump 版本会让缓存串台；不重标就不知道新判官与人对齐程度；
- 案例：Qwen → gpt-6-sol 换机时，旧时代读数封存、D0 基线重开。

# G. 数据与校验层（主场题，趁强打）

## G1 · lint 五类保护对象？

**口径**：协议可执行 / 引用完整 / 安全卫生 / **判据效力** / **防退化**——后两类是 okb 区别于普通数据集的关键。

**展开**：
- 协议可执行：E101 会话唯一、E102 编号连续、E103 phase 单调（write<disturb<update<probe）；
- 引用完整：E108/E113/E114/E115/E116；
- 安全卫生：E110 正则编译、E111 路径安全、E109/E117 PII、W210 跨样本冲突；
- 判据效力：E104 门槛、E112 boundary_kind、E118 矛盾断言、E120 失败形态可达、E121 组合前挡；
- 防退化：E119 空转、W206 trap 覆盖、W207 区分力、W208 事件恒真/恒假、W212 回声。

## G2 · 四档治理？现在 0E/61W 的构成？

**口径**：E 阻断构建 / 必零 W / 豁免 W（书面）/ 注记 W——不是所有警告都值得拦，但拦的必须清零或显式记账。

**展开**（v2 现状数字，可背）：
- 0 error；61 warning = W205 注记 ×52 + W207 豁免 ×9；
- **W206 / W208 / W212 已清零**（必零档）；
- 豁免要写理由（如 A2："区分力由 R_FILE_OLD 与 A3 承担"）。

## G3 · validate_plan 四件事？

**口径**：版本绑定 / 逐锚点 disposition / 检查字段合法 / 覆盖面闭合。

**展开**（对着真实代码口径讲）：
- 顶层必须是 `{format, paper_sha256, samples}`，且 `paper_sha256` 等于卷的实际 sha——**计划与卷同一冻结版本**（错配直接拒绝："plan paper/protocol mismatch"）；
- 每个样本 `{sample_id, anchor_disposition, checks}`：**逐锚点 disposition**（每个锚点 A* 记录 role/checks/reason——被哪条检查承接、理由是什么）；
- 每条检查 `{id, layer, on_failure, basis}`：失败映射必须在五类枚举内、basis（用户指令依据）必须非空；
- 样本必须在卷里存在且不重复、checks 非空、check id 唯一。

**证据落点**：`tools/scoring/four_layer.py::validate_plan`；`paper-v2.plan.json`（330 检查、sha 绑定 bca2c68c…）。

## G4 · anchorcal 死谓词/路径是什么？

**口径**：运行前探测谓词**动态活性**——正则能不能命中（不只是能不能编译）、路径能不能解析；死谓词=永远不匹配→锚点恒真/恒假→样本失去区分力。

**展开**：
- 与 E110 区别：E110 查**语法活性**（可编译）；anchorcal 查**语义活性**（能命中）；
- 现状：对旧全局语料报"死谓词 0 / 路径 0"；覆盖 12/92（新题待冒烟后复跑）——**这个覆盖数字要主动交底**。

## G5 · 装配链路的可复算意义？

**口径**：作者稿→正式卷→计划→断言库→质检，全链**确定性可复算**（同输入同 sha）——数据工程的高分实践。

**展开**：
- 链路：`v2_split_plan → build_stock_v2 → assemble_v2 → build_registry → qc_v2`；
- 三件套分工：`.yaml`（作者稿）→ `.fixed.yaml`（schema 兼容稿）→ `.plan.json`（计划）；
- 意义：任何一处改动都能重建出可对比的产物；评审可复现；"锁"可信。

## G6 · registry（断言库）是什么？

**口径**：629 个槽位的断言台账 = 330 条 plan_check + 299 条 anchor；每个槽带身份与分类 `{slot_id, kind, sample_id, dimension, layer, scope}`。

**展开**：
- slot_id 例：`s8c_long_001:R_R_MEMORY`；
- 用途：判分归因的定位坐标（finding 挂哪条断言）、判官校准（assertion-bench 38 项三态标签选优判官）、迭代管理的载体。
