# okb 评测规格说明书 v1.1

> 2026-09-29 路线更新：后续优化以[冲冠优化主方案 v1.0](championship-optimization-master-v1.md)为主；本文保留领域规格及原批准记录。新方案涉及双轴评分、证据范围和报告口径的调整须按[迁移决策](../notes/championship-design-decisions-v1.md)在后续版本实现，不追改历史。

## 0. 批准与范围

依据：项目负责人在对话明确批准上一轮方案，并要求“先让一小批真实任务从两款Agent执行，一直走到可信评分、人工核验和雷达图，形成完整闭环；再按同一条稳定链路扩到100题”。**设计方向已批准；实施和验收未完成**，不冒充A/B双签或独立专家审查。

规格版本不等于suite版本。冻结旧预注册不改，冲突由`notes/p5-amendment-v1.1.md`追加说明；其余不冲突约束保留。本文是当前设计入口，阶段0～9记录保留其当时状态。

## 1. 目标与交付

在openKylin统一组织对话、记忆记录、文件和行动证据，自动比较至少OpenClaw与Hermes的长期记忆能力。交付：方案文档；样例任务/真实证据/评分；源码、配置、脚本及复现README；支持批量对比的一键CLI；多维指标和雷达图；openKylin桌面双Agent真实演示录屏（建议3～5分钟）。GUI可选，.deb建议而非强制。

任务书权重：数据25%、自动评分25%、通用性15%、稳定复现15%、指标10%、创新落地10%。优先真实可信闭环，不以工具通过数量、候选数量代替最终成果。

## 2. 数据集

### 2.1 维度与规模

六维：长期保持、记忆调用、动态更新、相近区分、边界识别、任务复用。最终规划100题＝六维核心各15（90）＋深化10（时间3、强扰动3、多步复用4）。双Agent各3轮共600任务是项目实验目标，不是赛题硬要求；正式执行须先冻结且获预算授权。

取消原按成功verdict分正/负组、全局近似对半、每维至少5道刹车的准入门。apply_history/suppress_target可作描述标签，不强制45:45、不由absent自动推导、不将普通实体消歧一律计作抑制。边界维保留withhold≥10/release≥5；每题具正确行为与适当错误反例。

### 2.2 每题必备

稳定ID/版本、主维度与能力定义、用户指令及来源/对象/作用域、跨会话过程、必要时间和初始化文件、可观测正确结果、锚点或语义评分依据、执行前锁定的策略预期和定向错误对照、输入指纹及作者/审阅状态。

场景和产物应多样，不能全做固定JSON暗号。答复“记住了”不构成成功充分证据；应观察后续使用、记忆记录、文件或行动。无探针不能推断是否持久化。候选自测通过不自动获得正式配额。

### 2.3 深化

- 时间：写/改/探跨至少2个日历月，涉及相对时间或生效窗口，日期与预期绑定。改日期须新版本预期/锚点；E102/W206不是窗口验证器。
- 强扰动：写探之间至少3个不同话题会话，结构统计不能代替话题审读。
- 多步复用：至少2产物分别正确应用历史，每份独立检查。不擅加原文未要求的复杂推导门槛，也不将同值复制夸大为复杂推理。

## 3. 执行与取证

只操作专用评测实例。不同题隔离/重置评测记忆和工作区，同题保留所需跨会话状态。完整题目供引擎与评分器内部使用，Agent只收到指令、必要时间和初始文件，不收到答案/锚点/mock策略。

统一记录manifest、任务状态、完整相关对话、记忆前后快照、文件变化、工具/时间观测、raw引用、输入和代码指纹、重试与异常。先检测PII后脱敏落盘，物理字节与脱敏文本指纹域不得混用。新证据新run ID，历史只读。

环境故障、采集缺失、未证实探针和不可重建截断等须显式拒判并报告，不计成Agent遗忘。保留有效覆盖率和各类无效原因，不能静默删除。

## 4. 自动评分

先验证运行/证据，再判断能力。五类：remembered（正确记忆、使用或拒记）、omitted（遗漏）、confused（混淆）、wrongly_persisted（错误持久化）、wrongly_reused（错误作用域复用）。正确计1、能力错误计0；无效/不可判不混入能力0分。

确定性字段/值/禁止项规则优先；必要时模型判官处理合理改写和复杂语义。每条裁决输出类别、原因及证据引用。判官故障不算Agent失败，回放缓存不算新观测。

多错误时登记优先级并保存完整锚点向量；本规格不暗改现行hard首失败逻辑。含禁用对象的否定说明是否违规须逐题明示，不能把literal命中直接当人工真值。歧义未解暂不正式纳入。

## 5. 人工验证

单位：一次真实任务运行。两名真人独立查看用户脚本/时间、对话、记忆、文件与工具证据；不看自动判决、锚点描述、参考答案和对方标签。隐藏结构身份，披露自由文本识别风险。每例填写五类之一或unassessable、证据编号和一两句理由。标签绑定精确包SHA与随机行号，不可判不是第六能力分数。

流程：指南和训练示例 → 用不同案例独立标注 → 锁原始结果 → 算一致性 → 仲裁。不能先改一致再算κ。披露题目设计参与情况，AI不能代替真人。正式验证建议≥50真实案例、覆盖六维和双Agent，考虑重复题聚类；小批先核验全部有效案例，仅报告pilot，不外推正式κ。抽样、拒判分母及训练/验证隔离在发包前锁定。

## 6. 指标

六维正确率、每维有效n/覆盖率、五分类分布、withhold错误持久化率、release过度拒绝、环境/证据无效原因、多轮波动与适当不确定性。报告人工原始一致率、类别分布、不可判比例和κ适用限制。

pilot雷达标“探索性/非正式排名”，展示n和无效率。缺维不填0；达不到正式样本门不绕过工具生成正式总分，可另出清楚标识的诊断图。

## 7. 小批闭环与扩容

建议六维各2题，12题×2Agent×1轮＝24任务，边界含拒记/允许保存；具体清单与预算执行前锁定，数量建议不等于消费批准。先环境/探针控制，再真实运行、证据完整性、自动评分重放、双人核验、pilot雷达和复现命令。

失败保留记录，修复后新版本重跑；不以mock补真实成绩、不筛选漂亮结果。闭环通过后按同链路分批扩题，最终100题审查冻结、600任务正式实验和演示交付。pilot默认不并入最终独立验证集。

## 8. 用户已确认权限与当前状态

环境由队友管理；已有专用评测实例、允许重置；先估费用、用户再批准调用；用户认领一名真人，第二名稍后确定。不得索取/回显密钥，设计批准不代表无限消费授权。

旧VM地址只是历史资料，当前连接、模型价格、可执行硬预算由队友回执确认。独立review曾受资源上限阻塞，不以主代理自测冒充独立GO。新增D+1历史证据需单独核验，不直接视为新规格闭环完成。
