## 一、项目背景

大模型智能体正在进入办公、研发与个人助理场景，"能否长期、稳定、可控地记住用户信息"成为影响智能体可用性的关键能力。长期记忆既包括**应被保留**的稳定信息（偏好、路径、模板），也包括**应被识别并排除**的临时信息、敏感信息、风险指令与噪声。

当前 openKylin 生态已支持 OpenClaw、Hermes、KylinBot 等主流智能体框架，但缺少与之配套的**系统级自动化评测工具**，行业现状存在三大痛点：

1. **依赖人工检查，难以规模化**——记忆能力评测往往靠人看轨迹、翻文件；
2. **简单问答式验证覆盖不足**——无法覆盖真实使用中的冲突更新、相似干扰与行动复用；
3. **自动评分语义偏移**——难以稳定判断模型到底是"记住了""误记了"还是"不该记却记了"。

**okb 的目标**：在 openKylin 上，对通用智能体的长期记忆能力做**自动化、低人工、可复现、可扩展**的量化评测，产出多维指标（六维 + 覆盖率 + 风险指标）与**逐条可解释**的评分原因，用于跨智能体比较与持续优化。

## 二、技术架构

### 2.1 总览

```
被测 Agent（多款 · 适配器契约）
   │  引擎：清场 → 布置 → 发题 → 取证
   ▼
证据层：事件索引 evidence.jsonl + raw 真身（逐轮进程输出 / 记忆前后快照 / 文件差分）
   ▼
双轨评分：客观锚点（规则可复算） + 语义判官（三态判定 + 引用强约束）
   ▼
四层聚合：证据门 → 客观检查 → 语义检查 → 聚合与复核队列
   ▼
指标与报告：六维通过率 + 覆盖率 + 风险指标 + 雷达图 + 逐检查解释（结论/理由/引文）
```

### 2.2 核心组件

| 组件 | 职责 |
|---|---|
| `engine/` | 任务级清场、发题、逐轮独立进程调用、记忆/文件/回复取证（带扫描范围自证） |
| 适配器契约 | 引擎只发通用动作；适配器翻译成各 Agent 的 CLI 与文件布局（OpenClaw / Hermes / `cli_template` 声明式接入新智能体） |
| `v2/`（卷与计划） | 92 道多会话记忆题的确定性生成链：作者稿 → 计划 → 装配 → lint → 断言库（629 槽位） |
| 四层评分器 | 证据门 → 客观检查 → 语义判官（gpt-6.1-sol）→ 聚合；请求精确回放、预算账本 |
| 判词防线 | 极性/自足性 lint（E201/E202 阻断级）；引用校验不过=弃权；答案隔离 |
| `okb` CLI + `.deb` | 一键跑批/评分/报告；`agents.yaml` 导入不同智能体配置批量对比；openKylin 实测安装可用 |

### 2.3 关键工程机制

- **运行证据统一取证**：每个任务产出三层证据（事件索引、raw 真身、档案台账），记忆快照带扫描范围自证——"证据不是转述，是可审计的原件"；
- **可复现性**：同计划同请求**零调用回放**，评分结果与冻结值逐字节一致；openKylin VM 与宿主跨机复现一致；
- **稳定性证据**：同计划两轮 A/A，请求级翻转 1.25%（决定性翻转仅 0.12%），单批结论可引用；
- **字节冻结**：全仓换行/编码冻结（`* -text`），判官记录与输入指纹锁（input-lock）绑定。

## 三、应用场景

| 场景 | 用法与价值 |
|---|---|
| **openKylin 社区横评** | 同一套题、同一证据口径，对生态内多款智能体做可比的长期记忆能力评级 |
| **智能体开发回归** | 发版/调参前后跑记忆回归，用差异定位"哪条记忆坏了"；逐检查解释直接指向证据原文 |
| **持续评测（CI）** | `okb run` + 评分回放全离线可编排；批次数百任务分钟—小时级产出多维报告 |
| **研究与选型** | 六维通过率 + 覆盖率 + 风险指标并列；不刷单一总分，"不可判"如实披露 |
| **敏感场景验证** | 边界识别维（临时信息/敏感信息/风险指令）检验智能体的"该忘"与"该拒"能力 |

## 四、创新点

1. **运行证据驱动的自动评分，而非问答对错**：引擎统一组织对话、记忆、文件、行动轨迹为证据，自动判定**记住 / 遗漏 / 混淆 / 错误持久化 / 错误复用**五分类；
2. **判官可解释性硬约束**：语义判官必须给出真实证据编号 + JSON Pointer + 原文引用，引用校验不通过即**弃权**（而不是猜）；判官看不到答案标签（答案隔离）；
3. **判词极性机器防线**：requirement 一律归一化为"合规命题 + 显式映射"（94 条改写台账），极性/自足性由阻断级 lint 把关——从机制上消灭"判反了"这类系统性错误；
4. **少人工的可信度工程**：判官在正常链路零人工；人工只做**验证**——A/A 稳定性 + 检查项级盲审（AI 预筛 + 人工裁决单裁 48 例，人机一致 91.7%、κ 0.76、**0 假通过**）；
5. **诚实指标口径**：双口径披露（可判口径 + "不可判按失败"下界）、覆盖率门槛（不足只进雷达）、风险指标单列；"采不到 ≠ 没记住"；
6. **全链路离线可复现 + 多智能体可扩展**：零调用评分回放逐字节一致；openKylin 跨机验证；一键 CLI/.deb；`cli_template` 声明式接入第三个及以后的智能体。

## 五、成效（本批实测）

| 指标 | 数值 |
|---|---|
| 数据集 | 92 道多会话记忆题（六维配额；含动态更新 15、相近区分 15、任务复用 17） |
| 真实运行 | 552 任务（92 题 × 2 Agent × 3 轮），证据有效 552/552 |
| 自动评分 | 1674 条语义检查全量判定；零调用回放结果与冻结值**逐字节一致** |
| 数据质量校准 | 高区分 23 / 饱和 30 / 地板 9（item 台账） |
| 判官稳定性 | A/A 请求级翻转 1.25%（决定性 0.12%） |
| 人机校准 | 单裁 48 例：一致 91.7%（κ 0.76），0 假通过、2 误杀（已登记修订）、2 弃权 |
| 工程 | 921 项测试全绿；复算链 54 产物 0 漂移；`.deb` openKylin 实测安装可用 |

> **边界声明（如实披露）**：本批为探索性诊断——人审为单裁 48 例（AI 预筛 + 人工裁决，无第二人 κ）；覆盖率不足维度只进雷达；时间纵深/敏感样本偏薄。路线图与限制详见数据卡与方案说明文档。
