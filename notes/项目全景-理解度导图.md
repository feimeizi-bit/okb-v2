## ① 内容层：试卷与判据

**定位**：项目的核心数据资产——92 道记忆评测题，以及附在它们身上的完整判据体系。

**关键文件**
| 资产 | 文件 |
|---|---|
| 作者稿（存量修复 68） | `v2/01-paper-v2/stock-v2.yaml` + `stock-v2-repair-log.json` |
| 作者稿（新著 24） | `new-items-du.yaml` / `new-items-rest.yaml` |
| 模板与规范 | `sample-template.yaml`（头注释 8 条出题硬检） |
| 正式卷 | `paper-v2.yaml`（92 题，sha `bca2c68c…`） |
| 判据计划 | `paper-v2.plan.json`（四层计划，330 检查） |
| 断言库 | `v2/05-assertions/registry-v2.json`（629 槽 = 330 计划 + 299 锚点） |
| 台账 | `trap-ledger.json` / `stock-v2-repair-log.json` / `anchorcal-paper-v2.json` |
| 质检产物 | `v2/06-qc/{qc-v2-report.md, expect-cells-v2.json}`；`v2/00-wp0/`（旧卷逐题分级） |

**核心机制（能独立讲）**
- 题目五件套：`script`（多会话剧本）+ `fixture`（环境初态）+ `anchors`（结构护栏）+ `expect`（答案声明）+ `plan_checks`（语义判据）。
- 锚点三属性：`hard/soft` × `present/absent` × `on_violation`；六类证据通道（memory_entry / memory_read / memory_write / file_content / reply_text / tool_call）。
- **断言 = anchors ∪ plan_checks**；anchors 走规则执行、plan_checks 走判官执行；两类迭代机制分开。
- `trap` = 陷阱值清单（声明的危险值），需被锚点/计划承接才真正参与判分。
- 配额：六维 15/15/15/15/15+17；withhold 10 / release 5；深化槽 时间 3 / 强扰动 3 / 多步 ≥4。

**理解度：85%**
- ✅ 能独立：三层分工、trap、断言集合关系、配额逻辑、v1→v2 结构演进
- ⬜ 待补：域 lint 练习第 3 条；anchor 与 plan_check 的边界案例（哪些失败形态必须放计划层）

**学习来源**：M2 D1/D2/D3 + "拆解 okb"系列

## ② 构建层：确定性装配

**定位**：把作者稿"零件"确定性合成为三件套（卷 / 计划 / 断言库），同输入同 sha。

**关键文件**：`v2/02-generators/`
| 工具 | 作用 |
|---|---|
| `v2_split_plan.py` | 作者稿改动时先跑：拆出计划检查（plan_checks） |
| `build_stock_v2.py` | 存量 68 题选举 + 修复（两遍法 W207 注记） |
| `assemble_v2.py` | 92 题装配 → paper-v2 + 四层计划 → validate_plan |
| `build_registry.py` | 断言库 registry（629 槽位） |
| `qc_v2.py` | 质检总检（红线 1/3/4 + 历史失败模式对照） |

**核心机制**
- 装配 ≠ 拼接：同时做**结构重组**（内联的 `expect.plan_checks` 拆成独立计划文件）。
- 三件套分工：`.yaml`（作者稿）→ `.fixed.yaml`（schema 兼容稿）→ `.plan.json`（计划）。
- 可复算：`split → stock → assemble → registry → qc` 全链确定性，sha 已验证。

**理解度：80%**
- ✅ 能独立：讲清链路、"装配同时重组结构"、"校验要对正确版本的产物"
- ⬜ 待补：亲手跑一遍完整复算链（约 30 分钟）

**学习来源**：M2 装配与校验环节

## ③ 校验层：四关质检

**定位**：分层拦截，把坏样本挡在"进考场"之前；本项目的质量护城河。

**关键文件**：`tools/validate.py`（两层校验）、`tools/scoring/four_layer.py::validate_plan`、`tools/anchorcal.py`、`v2/06-qc/qc_v2.py`

**核心机制**
- 四关：**形状**（schema E001）→ **字段语义**（loader lint）→ **计划可追溯**（validate_plan）→ **死谓词**（anchorcal）。
- lint 全清单：`E001、E101-E121、W201-W212`。
- 五类保护对象：协议可执行 / 引用完整 / 安全卫生 / **判据效力** / **防退化**（后两类是 okb 的灵魂）。
- 治理四档：E 阻断 / 必零 W / 豁免 W（书面）/ 注记 W；现状 **0 error / 61 warning**（W206/208/212=0、W207×9 豁免、W205×52 注记）。
- `validate_plan` 四件事：sha 版本绑定 / 逐锚点 disposition（可溯源）/ 检查字段合法（on_failure 枚举 + basis 必填）/ 覆盖面闭合。
- 活体实验战果：注入 5 处破坏 → 全被抓住（E001/E101/E110/E104/E120，外加 W206 连带）。

**理解度：95%（最强项）**
- ✅ 能独立：四关、五类、四档、lint 四部件（编号/级别/消息/定位）、消息三段式、正在设计域 lint
- ⬜ 待补：负例测试文件的写法；域 lint 第 3 条

**学习来源**：M2 D3 + 活体实验

## ④ 引擎层：考场

**定位**：驱动真实 Agent 跑多会话剧本、采集全量证据、扛 16~20 小时长跑的机器。

**关键文件**：`engine/{runner, adapter, adapters/, collectors, merge_runs, timeanchor, workspace, redact}.py`；`docs/CONTRACT.md`；`docs/SETUP_VM_AGENTS.md`

**核心机制**
- 单 task 生命周期：health → reset → fixture → 前快照 → 会话循环（首轮注入时间前缀）→ 后快照 → diff → health_after → task_summary。
- 五态：`ok / timeout / agent_error / env_error / skip`；未预期异常一律 env_error（**不冤枉模型**）。
- 证据流：`ev_*` 事件（source/type/actor 六类通道）+ `raw/` 原始归档 + `pii_hits`；PII **先判定后替换**。
- 长跑防线：任务台账 / 断点续跑（checkpoint+rollback）/ 熔断 / watchdog / 预算 / 磁盘 / 信号 / 分片归并。
- 时间锚定方案 2：不改进程时钟，首轮注入 + 会话后归一化（TLS 证书坑的解法）。
- adapter 契约：`capabilities / reset / send / probe_memory`；mock 走 CONTRACT §14 stdio 协议。

**理解度：50%**
- ✅ 能独立：单 task 生命周期、五态映射、ev_* 行结构、时间锚定原理
- ⬜ 待补：续跑/熔断/分片归并的实操；watchdog 与 health 的边界

**学习来源**：早期"啃 okb"第 1 讲

## ⑤ 判分层：评分

**定位**：把证据变成五分类判定（remembered / omitted / confused / wp / wr）的引擎。

**关键文件**：`tools/score.py` + `tools/scoring/`（规则路）；`tools/score_four_layer.py` / `tools/scoring/four_layer.py` / `tools/scoring/fact_judge.py`（四层旁路）；`tools/report_four_layer.py`

**核心机制**
- 规则路十步定类：status 门 → precheck → 锚点求值四态 → 全部 hard+present 被 skip → task skip → **首条 hard 违反定类**（声明序）→ 全过取 expect → **guard#5** → soft 交判官。
- 不可判三闸：引擎能力预判（跑前）/ 锚点行级 skip（`SKIP_REASONS` 五枚举 + guard#5 + probe_unverified）/ 报告剔除公示。价值观：**宁可弃权，不可冤枉**。
- 四层评分：证据可信门 → 客观检查（file_exists / json_field_equals）→ 语义事实（判官三态 supported/contradicted/insufficient）→ 校准争议（复核队列）。
- 关键规则：mandatory 未决 → 整条 `unassessable`；**语义支持不能抹掉客观失败**；按计划顺序选失败类别。
- 判官工程：可见性包 §9（看不到答案）/ 缓存稳定投影 / 三态协议 + 引用校验（真实 ID/pointer/quote）。

**理解度：55%**
- ✅ 能独立：规则路（guard#5、首条违反、skip 家族）
- ⬜ 待补：判官三态协议细节；four_layer.py 实现；四层与旧 score.py 的并存关系

**学习来源**：早期"啃 okb"第 2 讲 + M2

## ⑥ 可信度层：人审与校准

**定位**：让分数"可被信任"——盲审、人机一致性、争议裁决。

**关键文件**：`docs/blind-annotation-protocol.md`、`tools/blind_annotation.py`、`tools/human-label.html/js`、`tools/make_f1_review.py`、`tools/kappa.py`、`tools/judge_drift.py`、`v2/05-assertions/bench/`（assertion-bench）

**核心机制**
- 盲审纪律：**先锁两份独立标签，后揭示机器/判官结果**（防标签污染）。
- F1 审题单：42 题变更面（24 新 + 18 修复）人审闭环。
- assertion-bench：38 项三态标签 → 判官候选选优。
- κ / 漂移：人机一致性 + 跨日稳定性（机制学过，未跑流程）。
- **现状：真人标签 = 0**（最大待回收资产）。

**理解度：35%**
- ✅ 能独立：讲清"为什么先锁后揭示"、κ 的作用
- ⬜ 待补：完整盲审流程；κ 实操；assertion-bench 流程

**学习来源**：M0（构念效度/κ）+ 手册走读
