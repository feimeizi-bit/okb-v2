# 断言与标准迭代更新机制设计 v1（Assertion Iteration Loop）

> **修订 v1.1（判官专用口径，2026-10-09）——覆盖前文 §0/§1/§7 的范围设定：**
>
> - **规则层（锚点/计划检查）不适用本机制**：每槽位 n≈1-3，覆盖率/误杀/漏判在统计上不可估计；
>   规则层用**设计期静态质检**一次性校准（lint W 码、anchorcal、F1 人审）+ 设计规则台账，
>   进入迭代只会造成无意义的"断言震荡"。
> - **本机制仅用于判官环节**：可迭代对象 = **判官实现包**（模型 / 线协议 / reasoning effort /
>   prompt 模板 / 输出契约版本）；语料 = 真人三态标签；指标按 **总体 + scope 分层 + 混淆矩阵**
>   统计（不做单槽位实现竞争）。
> - **按需触发**：换判官实现、判官门限不达标、模型换代时开一轮；不搭自动循环。
> - 资产调整：`registry-v2.json` 用途收窄为 **候选实现清单**（judge-candidates）；
>   bench 输入语义随之调整；语料/轮次台账/门限不变。

> 2026-10-09 · 目标：断言（锚点/计划检查）与判定标准可版本化迭代，
> 以「覆盖率 + 误判率（误杀/漏判）」为选择依据，自动挑选最优断言实现。
> 落位：v2 流水线的 WP2（断言库生成）与 WP5（评分校准）之间。

## 0. 概念模型（三层资产）

| 层 | 定义 | 稳定性 | 示例 |
|---|---|---|---|
| **槽位 Slot** | 「这道题/这个维度必须判对什么」的语义契约，有稳定 ID | 稳定，随卷冻结 | `v2_du_delay_approval_001:R_FILE_OLD`（生效日前文件须保持旧值） |
| **实现 Impl** | 满足槽位的具体可执行形式（可多候选） | 可迭代 | regex A / field_path 匹配 B / 语义判官 prompt v3 / 事件计数 C |
| **标准 Standard** | 门限 + 选择规则 + 版本 | 低频变更、显式登记 | FP≤5%、FN≤5%、覆盖率最大化、回放 100% 一致 |

关键原则：**槽位不变、实现可换**。判断"记得对/错"的语义契约属于卷；"怎么实现这个判断"属于可迭代资产。

## 1. 资产与目录（v2 新增）

```
assertions/
  registry-v2.json      # 槽位 → 实现列表 + 状态(incumbent/candidate/retired) + 指标台账 + 版本
  bench/                # 评测 harness（固定语料 × 候选实现 → 指标表）
  corpus/               # 语料：证据切片 + 真人三态标签（先来自盲审包，逐步扩到 600 跑批）
  runs/                 # 每轮评测凭据（语料 SHA、实现 SHA、指标、晋升决定）
```

## 2. 指标定义（全部可机械化）

| 指标 | 定义 | 目标 |
|---|---|---|
| **覆盖率** | 可判定槽位数 ÷ 应判定槽位数（证据就绪的） | 越高越好（≥90% 起步） |
| **误杀率 FP** | 人类判「支持」而实现判「违反」 | ≤5%（硬门） |
| **漏判率 FN** | 人类判「违反」而实现判「支持/未触发」 | ≤5%（硬门） |
| **不可判率** | 证据不足导致 insufficient 的占比 | 报告披露、不进 0 分 |
| **回放一致性** | 同输入重跑/回放判决是否逐字节一致 | 100%（硬门） |
| **成本** | token / 延迟（语义实现适用） | 次优先 |

出处对齐：GATES 的「三态正确率≥90%、误杀/漏判各≤5%、等价组一致率≥95%」直接作为 v2 的硬门来源。

## 3. 选择规则（字典序）

1. **硬门**：FP≤5% ∧ FN≤5% ∧ 回放一致；不满足者不得晋升做 incumbent；
2. **覆盖率最大**；
3. 稳定性（跨批次方差）最小；
4. 成本最低；
5. 复杂度最低（正则 < 字段匹配 < 判官）。

平局允许**双实现并行**（A/B incumbent），报告中并列披露，不隐藏。

## 4. 迭代流程（每轮固定六步）

1. **语料冻结**：从已采集证据中抽取版本化评测集；训/验分离（调参集 ≤70%，留出 ≥30% 不参与选择）；
2. **预注册**：候选实现与改动理由先登记（含预期指标变化）；
3. **评测**：harness 全量运行，产出指标台账（语料 SHA + 实现 SHA 绑定）；
4. **晋升**：满足硬门且字典序胜出 → 标记 incumbent；否则保留 candidate / 退役；
5. **登记**：CHANGELOG + 台账 + 断言库版本号（**与卷/计划版本绑定**）；
6. **定时重验**：新证据（600 批）到来即重跑，防漂移；跨版本比较须显式声明版本对。

## 5. 与现有资产的衔接（不重复造轮子）

| 现有资产 | 在新机制中的角色 |
|---|---|
| `anchorcal`（可执行性校准） | 实现层的第一步预检：path_never_produced / 恒真 / 死谓词 ⇒ 直接产生候选淘汰与覆盖率数据 |
| 四层计划检查（basis/on_failure） | 槽位定义来源（R_* / A*_content 等） |
| 盲审 38 项三态标签 | 语义槽位的首批真人校正标签（已发出，回收即入 corpus） |
| κ 协议（先锁后算） | 语料标签的质量保障；分歧样本只作 candidate 依据 |
| 判官缓存（模型戳隔离） | 语义实现的回放一致性保障 |
| GATES 评分器独立验证 | 从一次性验收升级为**每轮迭代的验收门** |

## 6. 防过拟合与防 Goodhart 护栏

1. 留出集 ≥30%、每轮轮换种子，绝不参与选择；
2. 单轮候选实现数量上限（≤5/槽位），变更理由强制写明；
3. 硬门双约束（FP 与 FN 同时约束），禁止"提高覆盖率换误杀"的作弊方向；
4. 语料标签：双人一致才进主集；单人标签进候选集且权重减半；
5. 每轮最多把 30% 的 incumbent 槽位换实现——防止全库漂移；
6. 所有轮次凭据不可回写；失败轮保留。

## 7. 落地步骤（对应 v2 排产）

1. **WP2 扩展**：生成器产出 `registry-v2.json`（槽位 + 初版实现）；
2. **WP5 升级**：评分校准工具改造为 `assertion-bench`：
   - 输入：corpus（批次三证据 + 38 项标签 + 后续 600 证据）、registry 候选
   - 输出：指标表 + 晋升建议 + 轮次凭据
3. **首轮评测时机**：两份盲审标签回收后（38 项真人三态）立即跑 v0 轮；
4. **报告口径**：数据卡披露断言库版本、逐槽位覆盖率/误杀/漏判、未达标处置台账。

## 8. 边界声明（防打脸）

- 本机制产出的是「**实现选择**」，不是"真理"；语义对错仍以真人标签与最终冻结为准；
- 不修改历史轮次、不追认旧成绩；断言库换版不等于卷换版（卷变更另走版本流程）；
- 未回收的真人标签（当前 0 条）不预填、不冒充。
