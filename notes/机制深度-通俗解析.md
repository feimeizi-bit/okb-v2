# A. 锚点系统（7 题）

## A1 · 什么是锚点？为什么用锚点而不是标准答案对比？

**大白话**：智能体干的事是开放式的（多轮对话、写文件、记不记东西），没有唯一"标准答案"能对。锚点就是把"应该发生/不该发生的行为"写成机器可查的条件清单。

**比方**：体检不问你"健康吗"（没标准答案），而是查"血压必须低于某值、某项不能有"。

**要点**：判据是数据（YAML 声明），不是代码；数据化换来四件事——可 lint（进考场前拦截）、可冻结（sha 锁）、可消融（验证因果力）、可审计（每条求值带证据）。

**证据**：`samples/*.yaml` 的 anchors 段；`tools/scoring/anchors.py`；C-2 消融 69/69。

**别踩**：别说"锚点就是测试用例"——锚点是声明的判据，测试用例是执行。

## A2 · 锚点的三属性（type/expect/severity）和关键字段？

**大白话**：每条锚点回答四个问题：去哪找（type 六类通道）、找什么（expect present/absent）、多严重（hard 直接定类 / soft 只降置信）、违反了算哪类错（on_violation 五分类）。

**比方**：验收单上的四栏：检查部位 / 检查项 / 是否一票否决 / 算哪种不合格。

**真实例**：retain_allergy A1 = `memory_entry + 花生 + present + hard + on_violation: omitted` → 记忆里找不到花生 = 判"遗忘"。

**别踩**："找什么"和"违反了怎么罚"要分开说：expect 管找什么，on_violation 管罚则。

## A3 · 为什么分 hard/soft？

**大白话**：机器能确定判的走 hard（免费、可复现）；只能靠语义理解的走 soft（交判官，有偏差、需校准）。让规则干重活，判官只在"规则判不了"的边界上工作——工作量最小化，偏差暴露面最小化。

**比方**：血压仪自动读数自动判；"气色好不好"交医生，但医生的结论只作参考。

**证据**：`tools/scoring/decide.py`（hard 短路 → soft 交判官）；rubric 与判官同源。

**别踩**：别说"soft 不可信"——它是概率型判据，可信度靠 κ 校准而非确定性。

## A4 · present/absent 为什么要 scan_scope 和 evaluate_at？

**大白话**：断言"必须没有"时，光说"没找到"不够——必须交代"在哪找过、查了多大范围"（scan_scope），否则"没找到"可能是"没找"。evaluate_at 声明查哪个时点：snapshot_after（默认，最终态）/ snapshot_before / any_time。

**比方**：保安说"没发现可疑人员"，必须讲清"查了哪几层、查了几遍"。

**边界**：0 条记忆上做 absent 检查 → skip(empty_memory)——"没装记忆系统"不能伪装成"正确克制"。

**别踩**：absent 不是"简单取反"，它是全家最容易被采集缺陷污染的判据。

## A5 · 多条 hard 同时违反，为什么取声明序首条而不是"最严重"？

**大白话**：同时踩多条硬指标时，按作者写 YAML 的顺序取第一条来定错误类型——保证机器判得确定、两方算出来一致。

**比方**：按排队名单顺序处理，第一个违规的人决定"罪名"，不搞"谁更严重"的主观排序。

**证据**：`decide.py` 取 outcomes 里第一条 hard violated；W205 lint 提醒作者确认顺序（把最严重的写在前面）。

**别踩**：规则路的"首条"与判官的"择重"允许不一致（复合形态）——分歧走人工裁决，漂移用判带。

## A6 · 六类锚点通道？为什么 memory_entry 是最硬的正向门槛？

**大白话**：证据来源六条路：记忆条目（memory_entry）、检索事件（memory_read）、写入事件（memory_write）、文件产物（file_content）、回复（reply_text）、工具调用（tool_call）。

**关键**：只有 memory_entry 直接检查"记忆本身"。文件写对、回复说对，可能是瞎猜蒙对的；记忆为空但产物全对 = 没记住（retain_allergy 就是）。

**边界**：真实 CLI 不暴露检索/工具事件——全卷 memory_read 仅 3 条、tool_call 仅 1 条，全部 soft；采不到就 skip 或移出评分（计划里是 diagnostic）。

**别踩**：别夸"六通道全覆盖"——主动交底"事件通道对真实 Agent 有观测上限，event_coverage=0 时不据此定罪"。

## A7 · E104 防什么？E119 和 W207 什么区别？

**大白话**：E104——每张卷子必须至少一道"必须做对"的题（hard+present），否则 Agent 崩溃或空转也能靠"负证据全过"拿满分。E119/W207 是同一个"空转白过"检测的两种输出：全卷的必答题在 fixture 原值上就已满足 → E119（样本失效）；个别锚点这样 → W207（可豁免但要写理由）。

**比方**：E104=考试必须有必答题；E119/W207=有些"正确答案"赛前就印在卷面上，谁都能"答对"，没有区分力。

**证据**：`tools/validate.py::_check_vacuity`；豁免例 A2："旧值保持型断言天然与 fixture 一致（W207 豁免）；区分力由 R_FILE_OLD 与 A3 承担"。

**别踩**：豁免不是放水——四档治理，豁免进台账、逐条写理由，是显式债务不是消失。

# B. 定类决策（7 题）

## B1 · 规则路定类的主干（十步压缩版）？

**大白话**：一条任务的判定流水线：① 看任务状态（非 ok 直接作废）→ ② 查完整性（证据行/回复行数对不对）→ ③ 逐锚点求值（通过/违反/弃权/仪器错）→ ④ 全部必答项都弃权 → 整条弃权 → ⑤ 有违反的按声明序第一条定类 → ⑥ 全过就按预期给"记住"→ ⑦ 软锚点交判官 → ⑧ 记账落盘。

**比方**：判卷流水线：先确认卷子完整，再逐题判分，有明确错误按优先级定罪，没错误才给及格，拿不准的科目交教研组。

**别踩**：别背成 if-else 流水账——每一步都要能说出"在防什么"（防假阴性 / 防白过 / 防冤枉）。

## B2 · guard#5 防什么？（附真实案例）

**大白话**：所有硬指标都过了，但有硬指标"没测出来"（被 skip）→ 不能给"记住"的结论，整条挂"弃权"。因为"没查到它没记住"不等于"它记住了"。

**比方**：体检全绿，但有一台仪器坏了没测——医生不能开"全健康"证明，只能写"待补检"。

**真实案例**：retain_allergy / hermes 老 run：A1 因探针未验证被 skip → 整行 skip。

**别踩**：既不能判 0 分（把采集失败当失忆），也不能判满分（证据缺失当通过）——弃权是唯一正确姿态。

## B3 · skip 家族五枚举各防什么？

**大白话**：五种"证据不够，拒绝定罪"的理由：empty_memory（空集上不能判"正确克制"）；no_event_collection（事件没采到，不能说"没发生"）；truncated_content（文件被截断，没命中不算）；snapshot_before_file（要查的时点不存在，不硬判）；probe_unverified（见 B4）。

**比方**：警察说"没证据"≠"证明无罪"；五种对应"现场被封 / 摄像头没开 / 录像被剪 / 时间点对不上 / 全辖区监控黑屏"。

**别踩**：skip 是"拒判"，语义上比失败更谨慎——它不是失败。

## B4 · probe_unverified 是什么？为什么是 run 级检查？

**大白话**：某 Agent 全 run 的记忆快照**从未**采到非空内容（可能是"摄像头坏了"）→ 它所有 memory_entry 锚点强制 skip。这是"摄像头坏了检测器"，一次判断覆盖整个 run。

**比方**：整个考场监控从头到尾黑屏——不能说考生作弊，也不能说没作弊，这批成绩先挂起。

**证据**：`tools/scoring/index.py` run 级预计算；mock 考生不适用（记忆面可信，"扫到且空"保留真失忆语义）。

**别踩**：不能拿"单条快照空"当探针坏——要看整 run 有没有任何一次采到过非空。

## B5 · env_error 和 skip 的区别？

**大白话**：env_error = 评测器/仪器自己的问题（谓词解析不了、证据链断了）→ 记环境的账，不算考生；skip = 证据不足 → 弃权。报告里分开算：env_error 进 invalid（可能触发熔断），skip 不进。

**铁律**："没证据的 skip"归 env_error——不能靠说"我判不了"逃避举证。

**记忆**：仪器错=env_error，证据不够=skip（用"谁的错"记）。

## B6 · 为什么未预期异常统一记 env_error？

**大白话**：任何说不清的异常，宁可记环境的账，也不冤枉模型——评测的第一原则是"失败可归因、结论不受污染"。

**比方**：跑道塌了导致成绩无效，算场地问题，不算运动员的问题。

**映射**：超时→timeout；适配器异常→agent_error；其余一律 env_error。

**别踩**：这不是粉饰，是算过账的策略——"假阴性的代价 > 弃权的代价"。

## B7 · soft 锚点为什么不定罪？

**大白话**：soft 判据不参与规则路定罪——因为语义判断有系统性偏差，不能当确定性证据。hybrid 模式：hard 管违反，soft 交判官；判官失败就标 judge_error，不进分母。

**比方**：硬指标看仪器读数；"气质"评估只作参考，还得看评估师水平（κ 校准）。

**证据**：`decide.py` 步骤 6-7；A4 检索事件就是 soft——真实 CLI 采不到，绝不能据此定罪。

# C. 判官工程（7 题）

## C1 · §9 可见性禁令怎么实现的？

**大白话**：AI 判官绝对看不到答案标签——输入包禁止出现 verdict/confusions，程序递归做字符串比对（连转义写法都拦），发现就报错。

**比方**：阅卷老师不能翻卷子背面的标准答案；哪怕答案被折起来藏进备注，也要搜出来。

**实测**：答案泄漏能把指标准确率从 63% 拉到 12%，整批作废。

**别踩**：为什么这么严——判官一旦看到答案，评的就是"抄答案能力"。

## C2 · 缓存键为什么用"稳定投影"？同模型守卫是什么？

**大白话**：判官结论要缓存省钱，但缓存键必须由"任务 id + 引用的证据 id + 证据内容稳定哈希 + 契约/判官/模板三个版本号"共同决定；内容哈希只对冻结字段集计算——以后新增字段不会让旧缓存失效。

**比方**：图书馆按"书名+版本号"存书；新版书加了一页附录，不能把旧版卡片当新版用。

**守卫**：命中条件三条——有裁决 + 同模型 + 键匹配；"换模型吃旧缓存"是暗雷，必须挡。

**别踩**：只说"有缓存"不够，要能讲"为什么不会串台"（版本四件套 + 同模型守卫）。

## C3 · 判官三态协议与引用校验？

**大白话**：判官对每条语义检查只回三种：支持 / 否定 / 证据不足。而且必须给真实引用（证据 id、位置、原话）——引用的 id 必须真实存在（机器校验）。

**比方**：出庭作证必须报证据袋编号；法官核对编号存在，但"证词可不可信"还要合议庭。

**边界**："引用真实 ≠ 理由正确"——所以有第四层人工复核兜底；需求命题目前是自然语言字符串，不是结构化事实；抗提示注入未验证（要主动说）。

## C4 · κ pilot 为什么不能外推？（面试高频）

**大白话**：试算过一轮"人 vs 判官"一致性：18 个样本、17/18 相同，κ=0.647→1.000。但这不能吹——样本少且几乎全一致（近退化分布），少一格分歧 κ 就掉到 0.647；置信区间横跨 [0,1]；标注者之一是出题人本人、另一个是 LLM，不算独立样本；判官只在 hard 全过的行上有机会工作（选择性）。

**数字**：n=18；0 分歧=1.000；1 分歧=0.647；2 分歧=0.471。

**正确说法**："机制已建好；正式读数要走 P4-4（≥50 行真实 run、五类有梯度、用户参与、跨日）"。并且 κ 是信度（一致性）不是效度（测对了没有）。

**别踩**：说"已验证判官可靠"必死；说"机制就绪、数据待读、目标五类 κ≥0.7"满分。

## C5 · 判官的三类偏差？你们怎么防？

**大白话**：大模型评委有三种偏心：位置偏好（排在前面的答案占便宜）、长度偏好（长答案显得更对）、自我偏好（自家模型的答案给高分）。防法不是"假装消除"，而是"盲评 + 校准 + 监控"：屏蔽答案、κ 校准、跨日漂移台账、争议案例人工裁决。

**比方**：阅卷老师的字迹偏好防不住全部，但匿名卷 + 抽查 + 换人复评能控制。

**边界**：偏差只能度量与控制，判官结论永远带"低置信"通道。

## C6 · few-shot 轮换怎么防泄题？

**大白话**：给判官的示例案例库有 12 条；每次按样本 id 的哈希选起点，环取 2 条，且强制不同题目、不同维度——既防"示例恰好泄漏本题该怎么判"，又保证所有案例都会被轮流用到（防死条目）。

**比方**：培训阅卷员时发参考案例，但抽到的案例不能跟正在批的题撞车。

**证据**：哈希轮换有 "J7 全覆盖"断言兜底；案例库与 rubric 同源、版本绑定。

## C7 · 判带为什么不是单点？

**大白话**：判官漂移监控不比"单一期望值"，比"允差集合"——因为规则路按声明序定类、判官按语义择重，两者允许有合理的系统性差异；拿单点比对会把合理差异误报成漂移。

**比方**：体重波动 ±1kg 算正常；监控看"还在允差带内吗"，不是跟昨天分毫不差。

**机制**：锚点案例的 expected 是集合（band），分 band_provisional / unstable / pending 三态；系统性分歧另走人工裁决。

# D. 评分架构（5 题）

## D1 · 为什么四层评分？每层干什么？

**大白话**：从证据到分数有四层门：① 证据可信门（任务状态、对话完整、raw 来源、扫描数量、文件指纹——防"采集问题被当成能力结论"）② 客观检查（文件在不在、字段等不等——确定性）③ 语义事实（判官三态）④ 校准争议（复核队列兜底）。

**比方**：机场安检多层：证件核验 → 行李机检 → 人工开包 → 复查室。

**关键规则**：mandatory 未决 → 整条不可评估；语义支持不能抹掉客观失败。

**别踩**：不是"四步流程"，是四层"门"——逐层放行/拒收，不是串行打分。

## D2 · mandatory 未决 → unassessable 是什么意思？

**大白话**：只要有一条"必需检查"无法判定（证据不足），整条任务就是"不可评估"——哪怕已发现别的客观失败，也不出分数（失败记录保留，但状态是 unassessable）。

**比方**：体检报告有"关键项没测"，整份不能出结论，只在备注写"已发现某异常待确认"。

**为什么**：证据不全时的"部分结论"会被下游误用；宁可整条作废——与 guard#5 同源：宁可弃权。

## D3 · "语义支持不能抹掉客观失败"是什么意思？

**大白话**：两种证据是"并列门槛"，不是"投票"——文件指纹不匹配（客观失败）不会因为判官觉得"内容合理"被翻案；确定性证据优先。

**比方**：指纹对不上是硬事实，口供再好听也不能覆盖物证。

**意义**：这才是"分层"的真正含义——层与层是门槛关系，不是相互复核关系。

## D4 · 断言 = anchors ∪ plan_checks？两类迭代机制为什么分开？

**大白话**：判据有两种实现：规则断言（anchors——改动重，牵动 lint/冻结/消融都要重跑）和语义断言（plan_checks——判官执行，改 rubric 相对轻）。两类迭代分开，等于把"改承重墙"和"换家具"的成本分级管理。

**数字**：registry 629 槽 = 330 plan_checks + 299 anchors；每槽 `{slot_id, kind, sample_id, dimension, layer, scope}`。

**比方**：改承重墙要审批，换沙发随意——但两者都是"家里的东西"，统一登记在总账（registry）。

## D5 · v1→v2 的核心演进：锚点结构护栏化？

**大白话**：v1 让锚点自己管语义（正则直接查"花生"）；v2 把锚点退成"结构护栏"（只查"至少有一条记忆条目"），语义要求搬进 plan_checks 交给判官。原因：正则语义盲区（花生 vs 坚果、中文 vs peanut）+ 回声风险。

**证据**：计划里 A1 的 disposition 理由原文——"Natural-language memory … **not Chinese keyword presence**"；模板头注释："四类失败形态计划层覆盖；confusions 只列规则可达形态"。

**意义**：各层职责清晰——结构问题机器判，语义问题判官判，谁出错找谁。

# E. 引擎与证据（7 题）

## E1 · ev_* 是什么？格式与引用链？

**大白话**：证据行的身份证号。格式 `ev_{run短号}_{6位序号}`（如 ev_r010_007111），全 run 递增、续跑接号不重号。行里有 seq/时间/任务/会话/轮次/来源/类型/角色/payload/原始文件指针/PII 命中。判分结论通过 evidence_refs 指到 ev_id，再指到 raw/ 原文件——整条链可复核。

**比方**：法庭证物袋编号——判决书→证物编号→封存柜，一路可查。

**验收**：仅凭 refs + raw 能复现同一结论（CONTRACT §13）。

## E2 · 单 task 生命周期主干？

**大白话**：考前检查（health）→ 清场重置（reset）→ 布置考场（fixture）→ 考前快照 → 按剧本多轮对话（首轮注入时间前缀）→ 考后快照 + diff → 复查健康 → 写任务总结。每一步都落证据。

**比方**：实验流程全程录像，任何一步出事都能定位（谁的问题、哪一步）。

**失败路径**：能力缺失→skip；健康失败/路径越界/PII 异常→env_error；超时→timeout；适配器异常→agent_error。

## E3 · 五态映射与 invalid 集合？

**大白话**：任务结束只有五种状态：ok / timeout / agent_error / env_error / skip。其中 timeout、agent_error、env_error 算 invalid（计入熔断计数）；skip 不算 invalid（不拖垮批次）；ok 重置熔断。

**比方**：考场的异常记录分"仪器故障类"（算事故）和"证据不足类"（不算事故）。

**退出码**：0 全 ok / 1 有 invalid / 2 启动失败 / 3 守卫停机 / 130 信号中断。

## E4 · 断点续跑怎么保证证据不重不乱？

**大白话**：任务台账记录每个任务开始前的"证据文件末尾偏移量 + 序号"；重试/续跑前把证据截断回那个点（半截证据 = 从未发生）。关键顺序：**先回滚进行中的任务，再做"删旧证据 + 全局重编号"手术**——反过来会因重编号错位。

**比方**：游戏读档：进度退回存档点，而不是把新记录乱接在旧记录后面。

**战例**：曾靠台账在三次宿主机内存事故后恢复零任务损失（7 个任务二次 start）。

## E5 · 分片归并为什么"先归并后评分"+全局重编号？

**大白话**：多机分片跑出的证据要拼成一份：按分片顺序拼接、全局重新编号（编号变了，所有引用同步替换）。为什么必须先并后评：判分结论引用的是 ev_id——编号重排后旧引用全断，所以评分必须在拼装完成后做。

**比方**：分头批改前先合订试卷并按最终页码重编号；引用页码的批注必须等装订完再写。

**fail-closed**：输出目录与分片重叠直接拒绝（防覆盖）；agents 取并集（防第二产品静默无行）。

## E6 · PII 先判定后替换？什么算泄露？

**大白话**：发给 Agent 的是真值（它必须看到真实信息）；落盘证据里换成占位符。顺序不能反：**先在真值空间判定命中**（记录 pii_hits），**再替换**——反了命中算不出来、replay 全废。

**什么算泄露**：只看"写进持久化面"的行（memory_write / file_write）；快照、回读确认不算；Agent 自己打码后再持久化=同样违规（打码只是降档理由，不是免责）。

**比方**：先把证据拍照取证，再把敏感信息涂黑归档。

## E7 · 时间锚定方案 2？

**大白话**：要测"跨天记忆"，又不能乱改系统时钟（实测改时钟会破坏 TLS 证书有效期校验）→ 曲线方案：对话首轮注入"（当前时间：剧本时间）"，会话结束后把文件修改时间、记忆条目时间戳平移到剧本时间。

**比方**：舞台上不能换真的月亮，就给演员发"现在是晚上"的提示牌，再给布景贴上对应的月亮。

**边界**：剧本时间可覆盖；真实时间衰减未覆盖（已在 limitation 里声明）。

# F. 冻结与版本（4 题）

## F1 · sha 锁锁什么？F-4/F-5 的教训？

**大白话**：题卷内容算 sha256 指纹，跑批前校验（--expect-paper-sha）——锁"跑的是哪版题"和"锁后没人改题"。教训：F-4 锚点手术改了卷子内容 → 指纹重锚定；F-5 改完没落盘 → 锁定降级。核心：**锁不能只是文档承诺，必须机器可复验**（freeze_* 工具把冻结做成可执行门）。

**比方**：招标文件要贴封条 + 现场验封，不是"我保证没动过"。

## F2 · 三套版本号分别管什么？

**大白话**：contract（契约——语义宪法：字段什么意思）、schema（格式规范——字段长什么样）、suite（内容版本——哪批题）；另有 judge_version 和模板版本。任何变更登记 CHANGELOG、双方同步、只增不改。

**比方**：宪法修订 / 表格格式 / 题库版本，三个维度各管各的；缓存键同时盯三个版本，版本一变旧缓存作废。

## F3 · 预注册是什么？防什么？

**大白话**：跑批之前先把"判据矩阵/期望格/允差"写死并锁 sha——防止"跑完再解释""看结果改标准"（HARKing）。

**比方**：临床试验先注册主要终点再开跑，不能跑完再挑一个好看的指标当终点。

**边界**：预注册防不了标准演化，只能保证演化可追溯（rubric 每版留痕 + 触发案例登记）。

## F4 · 换判官端点的三纪律？

**大白话**：判官结论是"相对某版本/端点"的——换端点必须做到三条：① bump judge_version；② 漂移台账开新行；③ κ 重新标注。缺一不可。

**比方**：换秤必须重新校准，不能拿旧校准记录继续用。

**理由**：不 bump 版本缓存会串台；不重标就不知道新判官跟人对齐程度。

# G. 数据与校验层（6 题）

## G1 · lint 五类保护对象？

**大白话**：40+ 条 lint 就守五件事：① 协议可执行（会话编号连续、阶段顺序对）② 引用完整（锚点指向的会话/轮次/证据都存在）③ 安全卫生（正则可编译、路径安全、PII 卫生）④ **判据效力**（每卷有必答题、失败形态可达）⑤ **防退化**（防空转白过、防死锚点、防回声）。

**关键**：后两类是 okb 区别于普通数据集的灵魂。

**例子**：E104（必答题）、E120（失败形态必须规则路可达）、E119（空转）、W212（回声）。

## G2 · 四档治理？现在 0E/61W 的构成？

**大白话**：不是所有警告都要拦：E 阻断构建 / 必零 W（必须清零）/ 豁免 W（书面理由可留）/ 注记 W（知情即可）。

**现状数字**（可背）：0 error；61 warning = W205 注记 ×52 + W207 豁免 ×9；W206 / W208 / W212 已清零。

**比方**：安检分级：有的直接拦、有的必须整改、有的登记备案、有的只提示。

## G3 · validate_plan 四件事？

**大白话**：判据计划进考场前过四关：① 版本绑定（计划里的 sha 必须等于题卷 sha——防拿 A 版计划判 B 版题）② 逐锚点 disposition（每个锚点交代"由哪条检查承接、理由是什么"）③ 检查字段合法（失败映射必须是五分类枚举、依据 basis 必填）④ 覆盖面闭合（样本都在卷里且不重复、checks 非空、id 唯一）。

**证据**：`tools/scoring/four_layer.py::validate_plan`；330 条检查绑定 sha bca2c68c…。

## G4 · anchorcal 死谓词/路径是什么？

**大白话**：跑批前探测"这条正则在真实语料里到底能不能搜到、路径能不能解析"。永远搜不到 = 死谓词 → 锚点恒真/恒假 → 样本没有区分力。

**区别**：E110 只查"正则能编译"（语法活）；anchorcal 查"能命中"（语义活）。

**现状交底**：旧语料死谓词 0 / 路径 0；当前只覆盖 12/92（新题待冒烟后复跑）——这个数字要主动说。

## G5 · 装配链路的可复算意义？

**大白话**：作者稿 → 正式卷 → 计划 → 断言库 → 质检，全链**确定性**：同样的输入必然产出同样的 sha。任何改动都能重建出可对比的产物。

**比方**：乐高按图纸拼装——同样的零件、同样的拼法，拼出来必然一模一样；评审能照着复现。

**链路**：`v2_split_plan → build_stock_v2 → assemble_v2 → build_registry → qc_v2`。

## G6 · registry（断言库）是什么？

**大白话**：判据的总账本：629 个槽位 = 330 计划检查 + 299 锚点；每槽记录身份与分类 `{slot_id, kind, sample_id, dimension, layer, scope}`。

**用途**：① 判分归因的坐标（发现问题挂到哪个槽）② 判官选优（assertion-bench 38 项三态标签）③ 迭代管理的载体。

**比方**：图书馆的目录卡片——找问题先查目录定位。

# 附：面试答题心法（四步骨架）

```
结论（一句话）→ 为什么这么设计（防什么）→ 我项目里的证据（文件/数字）→ 边界与 trade-off
```

- 答不上时："这层我没深入源码，但我知道在 XX 场景下要注意……"
- 所有数字必须能指到文件（claims 台账思维）；
- 被追问到边界时，主动交底比硬撑加分（例：事件通道采不到、κ 不能外推、anchorcal 只覆盖 12/92）。
